# 代理测活与出口

测活和账号验活共用代理地址转换：用户配置的 `socks5://` 在 curl_cffi 请求中使用
`socks5h://`，由代理解析目标域名，与 FlowRealm-Go 的 SOCKS5 dialer 保持一致。
数据库继续加密保存用户原始地址，转换不会修改账号密码或展示地址。
请求禁用环境代理与 `NO_PROXY`，显式代理不会被绕过，直连回退也不会继承环境代理。

自动检测向 `https://chatgpt.com/api/auth/csrf` 发送不带账号凭据的独立请求，测量到响应头的耗时。
默认每 5 分钟检测一次，延时隔离阈值为 1000ms；请求超时为 `max(5000ms, 阈值)`。
连接、DNS、SOCKS、TLS 失败或成功响应耗时超过阈值会隔离节点。
目标非 2xx 响应无法判定健康，保留原有分配资格或隔离状态。
隔离节点需连续两次收到 2xx 且耗时不超过阈值的 80% 才能恢复。
节点恢复后重新加入代理组选择；没有健康节点时返回验活暂不可用。

手动测活的请求超时为 15 秒。HTTP 500 以下表示代理链路可达，即使目标返回 403；
这不代表目标业务接口允许访问，也不会改变自动隔离状态。
失败请求的耗时只是失败前经过的时间，不是成功连通的延时。

健康观察按实际传输地址生成 SHA-256 指纹。旧版本本机 DNS 的 SOCKS5 记录在升级后失效，
1–30 秒错峰后重新探测，避免错误隔离状态沿用到新传输方式。
仅保存受控错误码、状态码和耗时，不记录上游异常文本或明文代理凭据。

`tests/test_proxy_transport.py` 使用本机 SOCKS5 测试服务与真实 curl_cffi 握手，检查
目标域名以 SOCKS 域名地址类型发送、编码凭据正确解码，以及 `NO_PROXY=*` 不绕过显式代理。
同文件通过本机 HTTP CONNECT 代理和受信任的测试 TLS 证书，验证无认证与带密码认证时，
测活和账号请求都能收到 HTTP 200，代理认证信息不会进入隧道中的目标请求。
HTTP 与 SOCKS5 必须使用服务商实际提供的协议和端口，不能仅通过替换地址前缀转换协议。
